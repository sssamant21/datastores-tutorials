# Part 2.12 --- Logging, Diagnostics, and Observability Configuration

**Status:** Revised Final / Canonical Edition\
**Target:** PostgreSQL 18

## Objective

Create a production logging and observability baseline that supports
incident response and performance analysis without generating
uncontrolled volume or exposing sensitive application data.

## Safety Model

Inspection is `[SAFE-READ]`. Persistent logging/statistics changes are
production changes and must be reviewed for performance, storage, cost,
and sensitive-data impact.

## 1. Observability Has Multiple Layers

``` text
PostgreSQL logs
PostgreSQL statistics views
query/statistics extensions
OS metrics
storage metrics
network metrics
service/orchestrator state
application telemetry
backup/replication monitoring
```

No single source is sufficient for production diagnosis.

## 2. Logging Baseline

``` sql
-- [SAFE-READ]
SELECT name, setting, unit, context, source, pending_restart
FROM pg_settings
WHERE name IN (
  'logging_collector',
  'log_destination',
  'log_directory',
  'log_filename',
  'log_rotation_age',
  'log_rotation_size',
  'log_truncate_on_rotation',
  'log_min_messages',
  'log_min_error_statement',
  'log_min_duration_statement',
  'log_connections',
  'log_disconnections',
  'log_checkpoints',
  'log_lock_waits',
  'log_lock_failures',
  'log_temp_files',
  'log_autovacuum_min_duration',
  'log_error_verbosity',
  'log_line_prefix',
  'compute_query_id',
  'track_activities',
  'track_counts',
  'track_io_timing',
  'track_wal_io_timing'
)
ORDER BY name;
```

## 3. Log Destination

PostgreSQL 18 supports multiple log destinations, including `stderr`,
`csvlog`, `jsonlog`, and `syslog` where supported; Windows also supports
event logging.

If using collector-managed file formats, validate:

``` text
directory
rotation
retention
ownership
filesystem capacity
central ingestion
backpressure/failure behavior
```

## 4. What to Log

Useful signals can include:

``` text
errors
connections/disconnections
checkpoints
lock waits
temporary files
autovacuum activity
slow statements
application identity
```

Do not enable maximum verbosity by default.

Broad statement or parameter logging can expose SQL text, literals,
credentials accidentally embedded by applications, PII/PHI, or other
sensitive data. Treat logging configuration as part of the data-security
design.

## 5. Runtime Statistics

PostgreSQL cumulative statistics are available through `pg_stat_*` and
`pg_statio_*` views when corresponding tracking is enabled.

Examples:

``` sql
-- [SAFE-READ]
SELECT datname, numbackends, xact_commit, xact_rollback,
       blks_read, blks_hit, temp_files, temp_bytes, deadlocks
FROM pg_stat_database
WHERE datname IS NOT NULL
ORDER BY datname;
```

Avoid resetting statistics as part of a tutorial acceptance check.

## 6. Query Visibility

`pg_stat_activity` can expose current activity to appropriately
privileged users. Generic acceptance output should avoid printing
complete query text.

For query-level history, an organization may choose
`pg_stat_statements`, but extension installation, preload requirements,
query-ID behavior, retention, privileges, and overhead must be managed
intentionally.

## 7. I/O Observability

PostgreSQL 18 includes database-side I/O statistics that can complement
host/cloud storage metrics.

Database statistics do not replace:

``` text
device latency
queue depth
IOPS
throughput
filesystem saturation
cloud volume limits
node-level CPU/memory pressure
```

Correlate both sides.

## 8. Alerting Design

Alerts should map to an operator action. Examples:

``` text
availability
connection saturation
replication lag
WAL/archive failure
filesystem capacity
backup failure
deadlocks
long-running transactions
autovacuum risk
checkpoint pressure
storage latency
error-rate increase
```

Avoid thresholds copied from another environment without capacity
context.

## 9. Production Checklist

``` text
[ ] log destination defined
[ ] rotation/retention defined
[ ] centralized ingestion monitored
[ ] sensitive-data exposure reviewed
[ ] required runtime statistics enabled
[ ] query visibility privileges controlled
[ ] storage/OS telemetry integrated
[ ] actionable alerts defined
[ ] backup/replication telemetry included
[ ] observability overhead reviewed
```
