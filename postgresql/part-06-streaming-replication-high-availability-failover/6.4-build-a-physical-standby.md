# Part 6.4 — Build a Physical Standby

**Target:** PostgreSQL 18  
**Status:** Revised Final / Canonical Edition — Pending Repository Validation  
**Lab:** `labs/build-standby.sh`  
**Classification:** STATE-CHANGING — DISPOSABLE TARGET ONLY

## Purpose
Build a PostgreSQL physical standby from an approved primary with `pg_basebackup`. A completed base backup is not a completed standby build: acceptance requires startup in recovery and bootstrap-level replication evidence.

> **Safety rule:** never prepare or replace an unverified `PGDATA`, and never run this exercise against an authoritative primary.

Parts 6.2 and 6.3 are prerequisites.

## Scope
This section covers target protection, `pg_basebackup`, streamed WAL during bootstrap, `--write-recovery-conf`, `standby.signal`, backup verification, startup, recovery-mode validation, and basic WAL-receiver evidence.

Detailed replay verification is 6.5, lag is 6.6, synchronous policy is 6.7, permanent-slot lifecycle is 6.8, and role transitions begin in 6.12.

## Bootstrap Flow
```text
Approved primary
      |
      | pg_basebackup
      v
Fresh standby PGDATA
      |
      +-- standby.signal
      +-- primary_conninfo
      v
pg_verifybackup
      v
start PostgreSQL
      v
pg_is_in_recovery() = true
      v
WAL receiver evidence
```

## Preconditions
Before construction:
```text
[ ] primary and disposable standby identities approved
[ ] PostgreSQL major-version compatibility validated
[ ] storage capacity validated
[ ] tablespaces assessed
[ ] network/DNS/time prerequisites accepted
[ ] replication identity/HBA/TLS/secret path accepted
[ ] WAL sender capacity accepted
[ ] backup/recovery readiness preserved
[ ] change owner and stop conditions known
```
A safety-critical FAIL or UNKNOWN means STOP.

## Target Protection
Never start with `rm -rf "$PGDATA"/*`. Prove the host, path, role, stopped process state, and tablespace handling first. Reject empty/relative paths and dangerous roots such as `/`, `/var`, `/var/lib`, `/usr`, `/etc`, and `/home`.

If an existing disposable PGDATA is present, quarantine/rename it where feasible rather than automatically deleting it. A partial failed bootstrap must not be silently reused.

## Primary Protection
If a local PostgreSQL cluster is reachable, verify its role before destructive preparation:
```sql
SELECT pg_is_in_recovery();
```
If a supposedly disposable target is writable (`false`), STOP and investigate. The approved primary remains authoritative.

## Tablespaces
User-defined tablespaces may live outside PGDATA. Validate source/destination paths, ownership, capacity, and collision risk. If mapping is unknown, STOP. The lab deliberately refuses to invent mappings.

## pg_basebackup
Canonical baseline:
```bash
pg_basebackup \
  --host="<primary>" \
  --port="5432" \
  --username="<replication-role>" \
  --pgdata="<standby-pgdata>" \
  --format=plain \
  --wal-method=stream \
  --write-recovery-conf \
  --progress
```
Authentication must use an approved mechanism. Never embed passwords in the repository or command arguments.

`--wal-method=stream` obtains required WAL through a replication connection. A permanent replication slot is not mandatory and is not automatically created here.

## PostgreSQL 18 Recovery Configuration
`-R/--write-recovery-conf` creates `standby.signal` and writes connection settings into the generated PostgreSQL configuration. Do not use legacy `recovery.conf`.

Treat `primary_conninfo` and `postgresql.auto.conf` as potentially sensitive evidence; do not dump them.

## Backup Verification
After successful transfer:
```bash
pg_verifybackup "$STANDBY_PGDATA"
```
Failure means FAIL / DO NOT START. Success validates the backup against its manifest but does not prove that PostgreSQL will start or stream.

## Startup and Acceptance
Service management differs by platform, so the reusable lab does not blindly call systemd or another manager.

After starting PostgreSQL with the approved mechanism:
```sql
SELECT pg_is_in_recovery();
```
Required result: `true`.

Then inspect:
```sql
SELECT status FROM pg_stat_wal_receiver;
```
Detailed LSN movement and replay evidence belong to 6.5.

## Production Blast Radius
A base backup can consume primary storage I/O, network bandwidth, WAL sender capacity, WAL resources, standby storage, and tablespace storage. `--max-rate` may be used as a planned transfer-rate guardrail.

## Secret Safety
Never enable `set -x`, print passwords/passfiles, dump `postgresql.auto.conf`, expose credential-bearing `primary_conninfo`, or store credentials in this lab.

## Failure Model
| Condition | Result |
|---|---|
| Wrong host or unsafe PGDATA | FAIL / STOP |
| Target identity uncertain | UNKNOWN / STOP |
| Writable local primary detected | FAIL / STOP |
| Target PostgreSQL running | FAIL / STOP |
| Primary unreachable/version incompatible | FAIL |
| Capacity insufficient | FAIL/UNKNOWN |
| Tablespace mapping unknown | UNKNOWN / STOP |
| Authentication/TLS failure | FAIL |
| `pg_basebackup` failure | FAIL |
| `pg_verifybackup` failure | FAIL / DO NOT START |
| Startup failure | FAIL |
| Expected standby has `pg_is_in_recovery() = false` | FAIL / STOP |
| WAL receiver unavailable | FAIL/UNKNOWN |

## Rollback / Rebuild
On partial failure: stop, preserve required diagnostics, quarantine the incomplete target, correct the cause, and rebuild cleanly. Do not modify the primary to match a failed standby.

## Hands-On Lab
Run `labs/build-standby.sh` only on an approved disposable standby. The script requires explicit environment variables and confirmation, refuses populated PGDATA, does not delete data automatically, and leaves startup to the approved environment-specific mechanism.

## Key Takeaways
- Standby construction is state-changing.
- Target identity and PGDATA safety are hard gates.
- Permanent replication slots are optional.
- PostgreSQL 18 uses `standby.signal`, not `recovery.conf`.
- Protect generated connection configuration.
- `pg_verifybackup` is necessary evidence, not complete standby acceptance.
- An expected standby must report `pg_is_in_recovery() = true`.
- Detailed streaming/replay validation follows in 6.5.
- Missing or ambiguous safety evidence means STOP.
